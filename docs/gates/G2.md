### G2-T2: `oris select`

**Modules.** All selection logic, defaults and data paths (GT CSV, `eval/split_v1.json`, blank-line classes) live in `eval/select_threshold.py`. The name `select.py` would shadow the stdlib `select` module and break asyncio.

**§10.6 rule.**
- `meets_bar`, `summed_correct`, `pick_qualifying`, `pick_fallback`, `cp_lower` and `TIE_WINDOW` move from `baseline_tfidf.py` into a new `eval/selection_rule.py`. They are generic over the threshold key, and `baseline_tfidf.py` imports them. B1's tests stay unchanged and green.
- Rule, verbatim from those functions, with thresholds ordered `T1` (strictest) to `T8`:
  - Qualifies ⇔ in EN and FR alike, matched ≥ 40 and P ≥ .95.
  - Q need not be contiguous.
  - If Q is non-empty: L = loosest in Q. Ship the strictest t ∈ Q with Σcorrect(t) ≥ Σcorrect(L) − 3, compared once against L.
  - Otherwise: argmax over t of the min-language CP-LB, where CP-LB = 0 when matched = 0 and ties go to the stricter. Label it "below the dev bar". The within-3 rule does not apply.
- Sensitivity rows, never shipped: (i) per language, the same rule on one language alone; (ii) `--target T`, the whole rule with .95 replaced by T.

**Mechanism (no src change).** For each B3 dev run and each `t` in `candidate_thresholds(manifest passes_k)`:
1. Write a tmp `policy.yaml`: `{<manifest requested_model>: {'<manifest library_sha256>': {policy_id: t, certified_by: dev_selection}}}`.
2. Re-decide:
   ```
   settings = cli.settings_from_manifest(cli.read_manifest(run))
   job = cli.replay_job(run, settings, tmp_policy, root)
   result, _ = cli.run_match(job, cli.prepare_run(job, settings, runtime), runtime)
   ```
3. `render_csv(result)` to a tmp CSV.
4. Abort unless mode `replay`, `policy_resolution == "override"`, `policy_id == t`, and 0 `LLM_FAILURE:replay_miss`.
5. Never read `config/policy.yaml`.

The model id always comes from the manifest, never from a constant.

**Scoring.** In process, with the runner's scorer (loaded by path as `run_experiment.load_scorer` does) and exactly the `score_argv` flags: `--reference --split --side dev --strict --classes`.

**Refusals (exit 4):**
- profile ≠ b3;
- `fallback_engaged`;
- EN and FR runs that differ in model, `library_sha256` or prompt_version;
- any `item_no` in `audit.jsonl` that is outside `item_ids_dev`.

**Output `eval/selection_v1.json`** (sorted keys, LF, portable paths):
- `inputs`: {run_ids, ledger_ids, model, input_sha256, library_sha256, split_sha256, reference_sha256, prompt_versions}.
- `rule`: {precision_bar .95, min_matched 40, tie_window 3, target}.
- `thresholds[]`: one entry per `T1`–`T8` with id, minimum {votes, attributes, confidence_bucket}, summed_correct and qualifies, plus per language:
  - matched, correct, precision, cp_lower_95;
  - coverage_labelled (correct/139, C₂₅₂);
  - h265 (diagnostic);
  - review_load_per_100 (needs_review per 100 lines, N basis, evaluation-protocol.md:87) and the needs_review count;
  - not_a_material, false_not_a_material;
  - mean_cost_usd (labelled "identical across thresholds (same calls)");
  - item_correct {Item No.: 0|1}.
- `reference_rows`: match-all (every valid in-library plurality top1 matched, never a candidate) and B2 (`R-10.9-evidence` outputs).
- `selected`: {threshold_id, status "meets the dev bar" | "below the dev bar", loosest_qualifying, dev_bar_met}.
- `sensitivity`: {per_language_optimum {en, fr}, target {value, threshold_id, status} | null}.

The trade-off table is rendered from the same data to `eval/selection_v1.md`.

**CLI.** `oris select` in cli.py is a passthrough identical in shape to `score_command` (cli.py:1072–1091): `allow_extra_args`, `ignore_unknown_options`, `add_help_option=False`, running `[sys.executable, root/"eval"/"select_threshold.py", *ctx.args]` and passing the exit code through. It contains no data-path literal.

### G2-T7: Error taxonomy

**Code first** (agent, TDD): `eval/errors_dev.py`.

- **Inputs:** the `B3-dev-sel` outputs and the T5 run folders (audit.jsonl top1/top2/rule/reason/raw_line_response), `data/boq_dataset_matched_GT.csv`, `eval/annotations/blank_line_classes.csv`, `eval/split_v1.json`, the inputs, and the global library. - **Output `eval/errors_dev.csv`:** exactly the evaluation-protocol.md §6 fields (item_id, lang, split, family = GT type else predicted type, kind, level_first_wrong ∈ {type, usage, subtype, decision}, usage_split, gt_suspect, gt_suspect_reason, cause, cause_2, evidence), plus top1, reason, v, labeller_a, labeller_b, adjudication_reason, provenance "builder labels (assistant panel)" and the date.
- **Kinds** are exactly as in protocol §6:
  - false_match = matched, labelled GT, triple ≠ GT;
  - match_on_blank = matched, GT blank (E/S/A);
  - false_nm = not_a_material on a labelled or E line;
  - missed = needs_review, top1 triple = GT;

### O12 · The B3 smoke refused 4 of 5 lines as BUDGET_CAP at a fifth of the cap

- **Seen:** run `20261006T001017Z-354cd333` (G2-T3, `B3-smoke-5`, EN, 5 slice items, `--budget-usd 0.10`). Pass 1 ran all 5 lines and pass 2 ran only `00.01.0030.`. - **Cause:** after each rendering's first batch, the service fans out the rest. 4 pass-1 calls in flight each reserved about $0.021, mostly `max_tokens` 4,096 × $5/M output. Together with $0.015 already spent, that took the ledger to about $0.099. Each pass-2 reservation (about $0.027 at the cache-write rate) then failed `spent + reserved + amount ≤ cap`, and `try_reserve` refused it permanently instead of waiting.
- **Meaning:** a defect. The cap was meant to bound spend, and it rejected work that fit. The smallest runs, including API requests under the A57 $0.10 floor, are most exposed.
- **Handled by:** A61, owner decision at pause #1. `BudgetLedger.reserve` waits for settlements and refuses only when spent + reservation > cap. Tests (`tests/test_llm_wrapper.py`): `test_concurrent_batches_wait_for_a_held_reservation_instead_of_failing` (the smoke in miniature, red before the fix), four ledger tests, `test_a_reservation_never_waits_when_nothing_is_in_flight` (float residue) and `test_a_waiting_dispatch_is_refused_when_the_breaker_trips_meanwhile`. The last two came from the adversarial review, and both were red before their fixes. `test_replay_reproduces_a_budget_cap_between_concurrent_batches` was rebuilt so that the refusal comes from actual spend; under A61 a hold alone no longer refuses. That is a spec-driven change, not test-fitting. The pre-A61 case, a refusal under a hold that replay must read back, is kept as `test_replay_keeps_a_refusal_the_recorded_run_made_under_a_hold`.
